# Tsukuyomi for Unreal

Unreal Engine 개발 지식을 모으고, 저장된 자료를 근거로 답하는 내부용 RAG 챗봇입니다. 팀에서 사용하는 기술 문서와 오류 해결 사례를 자연어로 검색하고, 답변에 인용된 출처와 검색 원문을 함께 확인할 수 있습니다.

Vue.js 웹 화면과 CLI를 제공하며, Python·FastAPI·LangGraph로 질문 처리와 검색을 구성합니다. 문서 임베딩은 로컬에서 실행하고, 질문에 따른 검색 담당 선택과 답변 작성에는 외부 LLM을 사용합니다.

## 무엇을 하나요?

- **기술 질문과 오류 해결**: 등록된 기술 설명, 오류 증상, 재현 방법, 해결 사례를 검색해 답합니다.
- **간단한 대화**: 인사·일반 상식·제공된 내용의 요약/번역/문장 수정은 Supervisor 판단에 따라 검색 없이 답합니다.
- **공개 웹 검색**: Tavily 키를 설정하면 Supervisor가 최신 공식 문서·패치 기록 등 공개 자료를 검색해 로컬 근거와 함께 활용합니다.
- **근거 확인**: 답변의 `[1]`, `[2]` 인용과 함께 문서 제목, 엔진 버전, PDF 쪽수 등 출처 정보를 표시합니다. 웹 화면에서는 인용된 검색 원문을 최대 1,000자까지 펼쳐볼 수 있습니다.
- **엔진 버전별 검색**: 특정 버전에 등록된 자료만 검색할 수 있습니다. 버전을 선택하지 않으면 전체 자료를 검색합니다.
- **지식 관리**: 웹 화면에서 기술·오류 해결 기록을 등록·검색·수정·삭제하고, 서버의 PDF·Markdown 문서 정보를 편집합니다.
- **근거 부족 안내**: 검색 결과가 없으면 필요한 엔진 버전·오류 로그·관련 자료를 요청합니다. 출처 번호 검증에 실패한 답변은 실패 안내로 대체합니다.

예를 들어 “UE 5.5에서 셰이더 컴파일 오류를 해결한 기록을 찾아줘”라고 질문할 수 있습니다. 실제 답변은 저장된 자료에 따라 달라집니다.

## 실행 방법

### 1. 환경 준비

Python 3.11 이상과 Node.js 22.12 이상이 필요합니다. 아래 명령은 macOS/Linux 기준이며 프로젝트 루트에서 실행합니다.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

`.env`에 사용할 LLM API 키를 설정합니다. 키는 저장소에 커밋하지 않습니다.

```dotenv
OPENAI_API_KEY=사용할_API_키
OPENAI_MODEL=gpt-5-mini
# 선택: 서버에서 사용할 Tavily 웹 검색 키
TAVILY_API_KEY=
```

`OPENAI_MODEL`은 프로젝트의 기본 설정값입니다. 사용하는 계정에서 접근할 수 있고 tool calling을 지원하는 모델로 변경할 수 있습니다. OpenAI 호환 제공자는 서버의 `OPENAI_BASE_URL`로 지정하며, 제공자별 호환성 확인이 필요합니다.

### 2. 백엔드 실행

```bash
uvicorn api:app --host 127.0.0.1 --port 8000
```

API 문서는 `http://127.0.0.1:8000/docs`에서 확인합니다. 현재 안내는 단일 API worker를 기준으로 합니다.

### 3. 웹 화면 실행

다른 터미널에서 프로젝트 루트를 기준으로 실행합니다.

```bash
cd frontend
npm ci
npm run dev
```

Vite가 출력하는 주소(기본 `http://127.0.0.1:5173`)를 엽니다. 개발 서버의 `/api` 요청은 `http://127.0.0.1:8000`으로 전달됩니다.

서버에 키를 설정하지 않았다면 **설정 → LLM 연결**에서 요청에 사용할 키를 입력할 수 있습니다. 입력 키는 서버를 통해 사용하며 브라우저 메모리에만 유지합니다. **LLM 연결 확인**은 키·모델과 tool calling 응답 형식을 검사하며, 외부 LLM 사용량이 발생할 수 있습니다.

### 4. 지식 준비 후 질문

**지식 저장소**에서 기술 또는 오류 해결 사례를 등록합니다. 제목·엔진 버전·내용은 필수이며, 오류 사례에는 재현 방법과 해결 방법도 필요합니다. 환경과 참고 URL을 함께 남길 수 있습니다.

기존 `.pdf`·`.md` 파일은 서버의 `data/unreal/docs/`에 넣습니다. **지식 저장소 → PDF · Markdown 문서 → 정보 편집**에서 제목·엔진 버전·출처 URL을 지정합니다. PDF는 텍스트 추출 가능한 문서를 지원하며, OCR과 웹 파일 업로드는 구현하지 않았습니다.

문서 변경은 다음 검색에서 자동으로 인덱스에 반영됩니다. 미리 인덱싱하려면 가상환경을 활성화한 프로젝트 루트에서 실행합니다.

```bash
python -m agents.docs
```

첫 인덱싱에는 `BAAI/bge-m3` 모델 다운로드와 로딩이 필요해 시간이 걸릴 수 있습니다. 서버 계정에는 `data/unreal/` 아래 문서·인덱스·잠금 파일을 생성할 쓰기 권한이 필요합니다.

검색은 **마이너 버전 계열**로 묶습니다. `5.4`를 선택하면 `5.4`, `5.4.1`, `5.4.2` 자료가 함께 검색되고 `5.3`·`5.5` 자료는 제외됩니다. API·CLI에 `5.4.2`를 지정해도 검색 범위는 `5.4` 계열입니다. 원본 패치 버전은 저장·출처에 그대로 유지합니다. `UE 5.4` 같은 비표준 표기는 기존처럼 문자열 정확 일치를 사용하며, 버전 미지정 문서는 특정 버전 검색에서 제외됩니다.

지식 등록에는 확인한 정확한 버전을 적고, PDF·Markdown 문서 정보에서는 여러 버전을 선택하거나 `5.4.2` 같은 패치를 추가할 수 있습니다. 패치별 영향·수정 시점·우회 방법은 확인된 근거와 함께 본문에 기록하세요. 답변은 질문에 적힌 패치와 검색 원문의 적용 조건을 참고합니다. 패치가 미지정이면 최신이라고 가정하지 않으며, 단순한 확인 기록을 수정 시점으로 해석하지 않도록 지시합니다. 패치 호환성을 자동으로 보증하거나 핫픽스 기록을 자동 수집하지는 않습니다.

### CLI 실행

웹 화면 없이도 질문할 수 있습니다. `.env`에 키가 없으면 숨김 입력으로 받습니다.

```bash
# 대화 모드 — exit, quit, q로 종료
python app.py

# 단일 질문
python app.py "Gameplay Ability System 관련 자료를 찾아줘"

# 엔진 버전 지정
python app.py --engine-version 5.5 "셰이더 오류 해결 기록을 찾아줘"
```

### 빌드한 화면을 백엔드에서 제공

```bash
npm --prefix frontend run build
```

빌드 후 API 서버를 다시 시작하면 `http://127.0.0.1:8000`에서 웹 화면과 API를 함께 제공합니다.

## 이전 대화 이어가기

사이드바의 **최근 대화**에서 이전 대화를 다시 열 수 있습니다. **새 대화**는 기존 기록을 보존하고 별도의 대화를 시작합니다. 대화별 메시지·검색 원문·코드 표시·검색 버전·작성 중인 초안을 유지하며, 선택한 대화의 같은 검색 버전에서 마지막 10개 메시지를 후속 질문에 전달합니다.

기록은 같은 주소·브라우저에 저장하며 서버나 다른 기기로 동기화하지 않습니다. API 키와 접근 토큰은 기록에 저장하지 않습니다. 연결 해제 시 화면에서 숨기고 내부 연결 확인에 성공하면 다시 불러옵니다. 저장한 대화는 목록의 삭제 버튼과 확인으로 지울 수 있습니다. 브라우저 저장소를 지우면 기록도 사라지며, 저장 실패는 화면에 안내합니다. 이 기능 도입 전에 이미 지워진 대화는 복구할 수 없습니다.

## 구현 방식

### 질문 처리: Supervisor 패턴

```text
Vue 웹 / CLI
    │ (웹 요청은 FastAPI 경유)
    ▼
Supervisor ──→ 직접 답변 (검색이 필요 없는 간단한 대화)
    │
    ├────────→ 기술 검색 / 오류 검색 / Tavily 웹 검색
    ▲                  │
    └──── 검색 결과 ────┘
    │ 검색 종료 후
    ▼
답변 작성 → 출처 번호 검증 → 답변과 인용 자료 반환
```

LangGraph의 Supervisor가 질문과 이전 대화를 보고 검색 필요성을 먼저 판단합니다. 인사·일반 상식·간단한 일반 개념 설명·제공된 내용의 요약/번역/문장 수정은 `direct_answer`에서 검색 없이 처리하며 출처를 붙이지 않습니다. 이 경로에서는 임베딩·인덱스·자료 지문에도 접근하지 않습니다. Unreal 기술/API·오류 해결·버전/패치·최신 정보·내부 지식·명시적인 검색 요청과 판단이 모호한 질문은 검색합니다. 질문 길이만으로 구분하지 않으며 판단은 LLM이 수행합니다.

검색 결과를 모아 Writer가 인용 번호를 포함한 답변을 생성합니다. 설명 문장에 인용이 있는지, 번호가 검색 자료 범위 안에 있는지 검사합니다. 코드의 배열 인덱스나 링크 속 번호는 인용으로 계산하지 않습니다. 이 검사는 답변 내용의 사실성까지 보증하지는 않습니다.

### 검색: 로컬 임베딩과 문자열 검색 결합

1. JSON 지식, Markdown, PDF를 읽고 메타데이터와 함께 최대 600자 단위로 나눕니다. 청크 간 중첩은 60자로 설정합니다.
2. `BAAI/bge-m3`로 정규화한 임베딩을 생성해 FAISS에 저장합니다.
3. 질문마다 벡터 후보와 문자쌍(bigram) 기반 문자열 후보를 각각 최대 30개 구하고 중복을 합칩니다.
4. 벡터 유사도·문자열 점수·자료 종류 선호 점수로 정렬해 검색당 상위 5개 청크를 반환합니다. 선택한 엔진 버전 필터는 두 후보 경로에 모두 적용합니다.

파일과 메타데이터의 지문으로 변경을 감지해 인덱스를 갱신합니다. 인덱스는 세대별로 저장하며 기본적으로 현재 세대와 직전 세대를 보관합니다. 질문 처리 중 자료가 변경되면 재질문을 안내해 서로 다른 시점의 근거가 섞이지 않게 합니다.

### Tavily 웹 검색

서버 `.env`에 `TAVILY_API_KEY`를 설정하고 API 서버 또는 CLI를 다시 시작합니다. “UE 5.4 핫픽스 내용을 공식 웹 문서에서 찾아줘”처럼 질문하면 Supervisor가 웹 담당을 선택할 수 있습니다. 키가 없으면 로컬 검색을 유지합니다.

웹 담당은 [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)에 공개 검색어를 보내고 최대 5개 문서의 발췌를 받습니다. Tavily 생성 답변·페이지 전체·이미지는 요청하지 않으며, 결과당 발췌는 최대 4,000자로 제한합니다. 결과는 원본 지식이나 FAISS에 자동 등록하지 않습니다.

웹 출처에는 URL과 검색 시각을 보존하고 화면에는 **웹 · 버전 미확인**으로 표시합니다. 검색어에 `5.4`가 들어갔다는 이유로 문서의 적용 버전을 확정하지 않습니다. 답변은 웹 발췌에 명시된 버전·패치 조건을 확인하도록 지시합니다. 인증·한도·연결 오류는 안내로 표시하며 로컬 근거가 있으면 그 범위로 답합니다.

검색어는 Tavily로 전송됩니다. 내부 문서 본문이나 대화 전체를 검색 요청에 자동으로 첨부하지 않으며, Supervisor에는 내부 이름·로그·개인 정보를 복사하지 않고 공개 기술명·오류 코드로 검색어를 작성하도록 지시합니다. 이는 모델 지침이며 자동 비식별화 보증은 아닙니다. 키는 서버에만 설정합니다.

## 설정과 데이터 처리

| 환경변수             | 용도                                       | 기본값                     |
| -------------------- | ------------------------------------------ | -------------------------- |
| `OPENAI_API_KEY`     | 서버에서 사용할 LLM API 키                 | 없음                       |
| `OPENAI_MODEL`       | 기본 LLM 모델                              | `gpt-5-mini`               |
| `TAVILY_API_KEY`     | 서버에서 사용할 선택형 웹 검색 키          | 없음                       |
| `OPENAI_BASE_URL`    | OpenAI 호환 API 주소                       | SDK 기본 주소              |
| `INTERNAL_API_TOKEN` | 모든 `/api/*` 요청에 적용할 공유 접근 토큰 | 비어 있으면 접근 확인 생략 |
| `RAG_MIN_SIMILARITY` | 검색 벡터 유사도 기준값                    | `0.45`                     |
| `LANGSMITH_TRACING`  | LangSmith 추적 활성화                      | 예제 설정 `false`          |

전체 설정 예시는 [.env.example](.env.example)을 참고하세요. `INTERNAL_API_TOKEN`을 설정했다면 웹의 **설정 → 내부 연결**에 같은 토큰을 입력합니다. 직접 API를 호출할 때는 `Authorization: Bearer <토큰>`을 사용합니다.

임베딩은 로컬에서 계산하지만 질문·대화 이력과 답변 작성에 필요한 검색 근거는 외부 LLM으로 전송됩니다. 웹에서 입력한 키·접근 토큰은 브라우저 메모리에만 유지하며 새로고침하면 지워집니다. 대화 기록은 같은 주소의 브라우저 localStorage에 저장해 새로고침 후에도 복원합니다. 기본 로컬 API 트레이스에는 질문·답변·키·검색 본문을 저장하지 않습니다.

LangSmith 추적을 켜면 질문·이력·검색 원문·답변이 LangSmith에도 전송됩니다. 추적 설정과 입력·출력 숨김 옵션은 [운영 안내](docs/OPERATIONS.md#langsmith-추적)를 참고하세요.

## 검증과 검색 품질 평가

가상환경을 활성화한 프로젝트 루트에서 실행합니다.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests
npm --prefix frontend test
npm --prefix frontend run build
```

기본 회귀 테스트는 외부 LLM과 임베딩 모델을 대체해 실행합니다. 실제 bge-m3 검사와 브라우저 검사는 선택 항목이며 [상세 검증 안내](docs/OPERATIONS.md#검증)에 실행 조건을 정리했습니다.

정답 문서 ID가 있는 평가 파일을 준비하면 외부 LLM 없이 검색 품질을 측정할 수 있습니다.

```bash
python -m agents.evaluate outputs/evaluation/cases.json --k 5 --output outputs/retrieval_eval.json
```

`cases.json`은 직접 준비해야 합니다. 파일 형식과 Hit Rate·Recall·MRR 등의 정의는 [검색 품질 평가](docs/EVALUATION.md)를 참고하세요. 이 평가는 검색 결과를 대상으로 하며 생성 답변의 정확도는 별도로 평가해야 합니다.
