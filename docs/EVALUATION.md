# 검색 품질 평가

팀이 확인한 질문·정답 문서 ID로 현재 RAG 검색을 평가한다. 기존 bge-m3·FAISS 검색을 사용하며 LLM API 키는 필요하지 않다. 첫 검색은 임베딩 모델 다운로드 및 인덱스 갱신을 수행할 수 있다.

## 평가 자료

아래는 **형식 예시**다. 실제 질문과 정답 ID로 바꿔 `outputs/evaluation/cases.json` 등에 저장한다. 검색 원본 디렉터리에 평가 파일을 넣지 않는다.

```json
{
  "cases": [
    {
      "id": "shader-55",
      "question": "UE 5.5에서 셰이더 오류를 해결한 기록을 찾아줘",
      "expected_doc_ids": ["<실제_문서_ID>"],
      "engine_version": "5.5",
      "kind": "error"
    },
    {
      "id": "missing-version",
      "question": "등록되지 않은 버전의 오류 해결 기록",
      "expected_doc_ids": [],
      "engine_version": "<자료가_없는_버전>"
    }
  ]
}
```

- `id`: 질문별 고유 ID.
- `expected_doc_ids`: 확인된 정답 문서 ID 목록. 근거가 없어야 하는 질문은 명시적으로 빈 목록을 쓴다.
- `engine_version`: 선택 항목. 같은 마이너 버전 계열 자료를 검색한다. `5.4`와 `5.4.2`는 모두 `5.4` 계열이며 정답 문서에도 같은 규칙을 적용한다. 비표준 표기는 문자열 정확 일치를 유지한다.
- `kind`: 선택 항목. `technique` 또는 `error`를 기존 검색의 종류 선호값으로 전달한다.

폼 등록 문서는 `GET /api/knowledge`의 `entries[].id`를 사용한다. PDF/Markdown은 확장자를 뺀 파일명이 문서 ID다. 문서가 없거나 정답 버전이 맞지 않으면 평가 전에 오류를 반환한다. 질문은 1개 이상 필요하며, 중복 질문 ID를 허용하지 않는다.

서로 다른 원본의 문서 ID가 같으면 평가를 중단하고 이전 보고서를 보존한다. 예를 들어 `Guide.md`와 `Guide.pdf`는 같은 ID이므로 서버에서 PDF/Markdown 파일명을 구분한 뒤 문서 정보와 정답 ID도 갱신한다. 파일명을 자동으로 변경하지 않는다.

## 실행

```bash
python -m agents.evaluate outputs/evaluation/cases.json --k 5 --output outputs/retrieval_eval.json
```

`k`는 실제 검색 청크 수이며 1~10, 기본값은 5다. `--output`을 생략하면 표준 출력만 사용한다. 기존 보고서는 전체 평가·검증에 성공했을 때 교체한다. 평가 파일·원본 문서·인덱스 경로에 보고서를 저장할 수 없다. 실행 중 자료가 변경되면 다시 평가해야 한다.

## 지표 해석

| 지표 | 계산 대상과 의미 |
| --- | --- |
| `hit_rate_at_k` | 정답이 있는 질문 중 상위 k개 청크에 정답 문서가 하나라도 있는 비율 |
| `recall_at_k` | 질문별로 찾은 고유 정답 문서 수 / 전체 고유 정답 문서 수의 평균 |
| `mrr_at_k` | 첫 정답 청크의 실제 순위 역수 평균. 검색 실패는 0 |
| `correct_rejection_rate` | 정답 목록이 빈 질문 중 검색 결과가 비어 있는 비율 |

모든 지표는 0~1이다. 해당 질문 그룹이 없으면 `null`이다. 같은 문서의 여러 청크는 재현율에 중복 반영하지 않으며, MRR은 실제 청크 순서를 유지한다. 정답 없는 질문을 Hit Rate·Recall·MRR 분모에 넣지 않는다.

보고서는 질문 ID·정답 ID·검색 문서 순위·빠진 정답 ID와 함께 자료/코드 해시, 임베딩 모델·검색 설정을 기록한다. 질문 본문과 검색 문서 내용은 보고서에 복사하지 않는다.

`settings.candidates`는 벡터 후보 수, `settings.keyword_candidates`는 최소 bigram 점수를 넘는 문자열 후보 수의 상한이다. 현재 각각 30개이며 같은 버전 필터를 적용하고 중복을 합친 뒤 기존 점수식으로 상위 `k`개를 반환한다. 문자열 후보에도 저장된 정규화 벡터의 실제 거리를 반영한다. 버전 비교 정책은 `settings.version_match_policy`에 `major_minor_numeric_else_exact`로 기록한다. 이 필드가 없는 이전 보고서는 정확 일치 정책일 수 있으므로 새 정책으로 다시 평가한다. 이전 보고서와 비교할 때는 같은 질문 목록으로 다시 평가하고 검색 코드 해시와 버전 비교 정책도 확인한다.

종료 코드는 0=평가 실행 성공, 1=입력/검색/저장 오류, 2=명령 인자 오류다. 실제 팀 자료의 목표 점수와 합격 기준은 아직 정하지 않았다. 이 도구는 단일 검색 호출을 평가하며, Supervisor 재검색과 생성 답변의 사실성은 별도 평가가 필요하다.
